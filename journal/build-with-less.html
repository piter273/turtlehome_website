用更少的东西，构建更长久的网站

关于我们如何理解技术、社区，以及值得长期坚持的事。

先问：页面真正需要什么？

一个介绍团队、展示项目、发布文章的网站，首先需要的是清楚的内容、可靠的链接和顺畅的阅读体验。它未必需要数据库、运行时渲染或复杂的依赖链。从静态 HTML 开始，是一种把问题缩小的办法。

少一个依赖，少一种维护

依赖本身不是坏事。但每增加一个工具，也会增加版本升级、兼容性和安全维护的责任。对于小型站点，浏览器原生的布局、动画和交互能力，往往已经足够。选择工具时，应该比较它解决的问题与它引入的长期成本。

先让内容可读，再添加交互

链接应该真的指向内容，按钮应该执行明确的操作。没有 JavaScript 时，读者仍然应当能够阅读文章、跳转页面、展开原生的详情区域。动画可以增强节奏，但不应成为看见正文的前提。

性能是一种体贴

避免自动播放的视频，不强迫读者下载大型字体，让非首屏图片延迟加载。这些选择能减少流量与等待，也让低性能设备获得更平等的体验。减少动态效果的系统偏好，同样值得被认真对待。

部署简单，迭代才轻松

将 HTML、CSS、JavaScript 和图片直接部署到静态托管服务，可以省去应用服务器的维护。本网站采用这一方式，不依赖付费 API 或常驻后端。需要更复杂的功能时，再根据真实需求增加复杂度，而不是预先承担它。
